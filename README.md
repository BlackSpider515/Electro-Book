# Электронный дневник

SPA для студенческого дневника и кабинета преподавателя: журнал группы, задания, загрузка работ, просмотр файлов, аннотации «маркером» и оценки звёздами.

Стек: Vite + React 18 + TypeScript + React Router (HashRouter). Бэкенд — Supabase (Postgres, Auth, Storage, Edge Functions). Без Supabase приложение автоматически работает в демо-режиме на `localStorage` + IndexedDB.

## Быстрый старт (демо)

```bash
npm install
npm run dev
```

Откройте:

- студент: `http://localhost:5173/#/`
- преподаватель: `http://localhost:5173/#/admin`

Демо-доступ преподавателя:

По умолчанию в демо-базе есть только группы `211` и `311`. Студентов и заданий нет: студенты появляются после регистрации, задания добавляет преподаватель. Демо-данные хранятся только в текущем браузере. Сбросить их можно кнопкой «сбросить» в подвале.

## Production: Supabase

### 1. Создайте проект

Создайте проект в Supabase и возьмите:

- `Project URL` — в Project Settings → API;
- `anon public key` — там же.

`service_role` в фронтенд не попадает и в репозиторий не коммитится.

### 2. Выполните SQL по порядку

В Supabase SQL Editor выполните миграции из `supabase/migrations/` строго по именам:

1. `20260101000001_schema.sql` — таблицы, индексы, ограничения.
2. `20260101000002_rls.sql` — RLS-политики и helper-функции.
3. `20260101000003_storage.sql` — приватный бакет `submissions`, лимит 50 МБ и политики Storage.
4. `20260101000004_seed.sql` — только группы `211` и `311`. Студентов и заданий там нет.
5. `20260101000005_group_delete.sql` — безопасное удаление пустой группы преподавателем.
6. `20260101000006_neutral_subject.sql` — нейтральное название дисциплины по умолчанию.
7. `20260101000007_submission_hardening.sql` — запрет сдавать без файла, менять студента/задание/оценку и подделывать историю версий.

Если база уже создавалась раньше, новые миграции `5`, `6` и `7` нужно выполнить дополнительно. Миграция `7` идемпотентна: её можно запускать повторно.

### 3. Бакет Storage

Миграция создаёт приватный бакет `submissions`:

- public: `false`;
- лимит файла: `52428800` байт (50 МБ);
- путь: `{student_id}/{assignment_id}/{uuid}.{ext}`;
- доступ — только владелец работы или преподаватель;
- просмотр — через signed URL.

Если бакет создаётся вручную, задайте те же параметры и выполните политики из `20260101000003_storage.sql`.

### 4. Edge Function регистрации

Функция `register` создаёт `auth.users` и профиль студента через `service_role`, возвращая логин и пароль один раз.

```bash
supabase functions deploy register --no-verify-jwt
```

Секреты `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase передаёт функции автоматически. Ключ `service_role` нельзя добавлять в `.env` фронтенда или в GitHub Variables/Secrets, которые попадают в клиентскую сборку.

### 5. Преподаватель

1. В Dashboard → Authentication → Users создайте пользователя:
   - email: `ksenia@diary.local`
   - пароль: `Ksenia2026!` (можно заменить на свой)
   - подтвердите email вручную.
2. Выполните `supabase/make_admin.sql`. Скрипт найдёт пользователя по email и создаст/обновит профиль с ролью `admin`.
3. Вход преподавателя: логин `ksenia` (или полный email) и пароль, заданный в Dashboard.

Пароль преподавателя хранится только в Supabase Auth. В коде приложения его нет.

### 6. Переменные окружения

Скопируйте `.env.example` в `.env`:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR-ANON-KEY
VITE_DEMO_MODE=false
VITE_SUBJECT_NAME=Учебная дисциплина
VITE_ENABLE_EDITING=false
VITE_ONLYOFFICE_URL=
```

Файл `.env` уже добавлен в `.gitignore`.

Если `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` не заданы или включён `VITE_DEMO_MODE=true`, приложение работает в демо-режиме.

## GitHub Pages

В репозитории есть workflow `.github/workflows/deploy.yml`. Он собирает проект и публикует `dist`.

1. Создайте GitHub-репозиторий и запушьте проект в ветку `main`.
2. В Settings → Pages выберите источник **GitHub Actions**.
3. В Settings → Secrets and variables → Actions добавьте:
   - Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, при необходимости `VITE_SUBJECT_NAME`, `VITE_ENABLE_EDITING`, `VITE_ONLYOFFICE_URL`;
   - либо те же значения как Secrets, если предпочитаете их скрывать. Workflow читает сначала Variables, затем Secrets.
4. Запустите workflow `Deploy to GitHub Pages` или сделайте push в `main`.

`VITE_BASE` workflow выставляет автоматически как `/<имя-репозитория>/`. Приложение использует HashRouter, поэтому маршруты вида `/#/admin` работают на GitHub Pages без дополнительной настройки rewrite.

## Правила и ограничения

- Студент видит только свою группу и свои работы.
- Преподаватель видит все группы, задания, работы и оценки.
- Регистрация: ФИО + группа. Дубликат «ФИО + группа» запрещён.
- Логин студента генерируется один раз, пароль показывается один раз. Технический email: `login@diary.local`.
- Задания по умолчанию не создаются. Их добавляет преподаватель.
- Группы по умолчанию: `211` и `311`. Преподаватель может добавлять и переименовывать группы.
- Удалить можно только группу без студентов. Если в группе есть студенты, интерфейс и SQL-функция `delete_group` не дадут её удалить. Задания пустой группы удаляются вместе с ней.
- Оценка — 1–5 звёзд. После выставления оценки работа блокируется от замены.
- Комментарии «маркера» хранятся в БД; писать их может только преподаватель, студент видит их в режиме чтения.
- Безопасность обеспечивается RLS и политиками Storage, а не только интерфейсом.

## Файлы

Разрешены: `doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx`, `pdf`, `txt`, `zip`, `rar`, `mp4`.

- Максимальный размер: 50 МБ.
- Файлы приватные, выдаются по signed URL.
- PDF — PDF.js; DOCX — `docx-preview`; XLSX — SheetJS; PPTX — превью/скачивание; TXT — чтение; MP4 — встроенный плеер; ZIP — список файлов.
- Старые `.doc`, `.xls`, `.ppt` и `.rar` не рендерятся в браузере и предлагаются для скачивания.
- Аннотации: PDF — страница + прямоугольник; DOCX/TXT — диапазон текста. Комментарий хранится отдельно от файла.

Полноценное редактирование Word в браузере с сохранением всех стилей, колонтитулов и режима правок требует серверного движка (например, ONLYOFFICE Docs). Текущий просмотрщик ориентирован на корректное отображение документа, а не на его редактирование.

## Демо-режим и сон Supabase

Бесплатный проект Supabase может засыпать после простоя. При первом запросе после сна возможна задержка или ошибка сети — повторите действие через 10–30 секунд. Для учебной нагрузки этого достаточно; при постоянной работе нужен платный план или внешний пингер.

Демо-режим не требует сети и не отправляет данные на сервер. Очистка данных браузера или кнопка «сбросить» возвращает состояние по умолчанию: группы `211`/`311`, без студентов и заданий.
